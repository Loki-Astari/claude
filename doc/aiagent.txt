1. INTRODUCTION                                         *aiagent-introduction*

AIAgent.nvim integrates AI agent CLIs (Claude Code, Aider, Gemini, etc.) into
Neovim as a persistent terminal split. Features include:

  - Right-side terminal split with optional keybind header
  - Multiple named agents running simultaneously
  - Per-agent color theming via the agent's own /color command
  - Git worktree support (isolated branches per agent)
  - Visual selection and open-buffer context sending
  - LSP diagnostics integration (whole file or visual range)
  - Scroll mode with position memory
  - Bufferline tab integration
  - Idle attention alerts when a background agent finishes or needs input
  - Lualine integration: agent mode, worktree branch, and MCP server status
  - Prompt history: per-prompt before/after diff viewer
  - PR review: read a GitHub pull request locally and submit the review

==============================================================================
2. REQUIREMENTS                                         *aiagent-requirements*

  - Neovim >= 0.9
  - At least one supported AI agent CLI installed in PATH

Supported CLIs:
  claude       Anthropic Claude Code
  cursor-agent Cursor AI
  aider        Aider (aider-chat)
  gemini       Google Gemini CLI
  codex        OpenAI Codex CLI
  goose        Block's Goose
  plandex      Plandex
  cody         Sourcegraph Cody
  amp          Amp

Optional:
  plenary.nvim Required only to run the test suite

  require('aiagent').setup({

    min_width           = 20,

      comment_file = 'cf',   -- comment on the whole file

4. CONFIGURATION                                           *aiagent-config*

All options are passed to |aiagent-setup|. Defaults are shown.

                                                     *aiagent-config-width*
width ~
  Type: number  Default: `0.4`
  Width of the terminal split.
  - 0 < width <= 1  →  fraction of total editor width
  - width > 1       →  absolute column count

                                               *aiagent-config-auto_resize*
auto_resize ~
  Type: boolean  Default: `true`
  Keep the agent column's share of the screen when the terminal itself is
  resized — e.g. after unplugging an external monitor. On |VimResized| the
  pane is set back to the same fraction of the (new) screen width it had
  before, clamped by |aiagent-config-min_width|.

  The fraction tracked is the one actually in use, not |aiagent-config-width|:
  if you drag the split to a different size, that new share is what is
  restored. Set to `false` to leave resizing entirely to Neovim.

                                                 *aiagent-config-min_width*
min_width ~
  Type: number  Default: `20`
  Minimum columns for the agent column, and the minimum left for the rest
  of the layout beside it. On a screen too narrow to satisfy both, the
  floor drops to half the screen.

                                              *aiagent-config-default_agent*
default_agent ~
  Type: string  Default: `"claude"`
  Symbolic name of the agent used for new terminals. Must be a key in
  |aiagent-config-known_agents|.

                                          *aiagent-config-auto_send_context*
auto_send_context ~
  Type: boolean  Default: `false`
  When `true`, automatically send unsent open buffers as @file context
  each time the agent window is focused.

                                        *aiagent-config-agent_startup_delay*
agent_startup_delay ~
  Type: number  Default: `1500`
  Milliseconds to wait after starting the agent before sending the
  `/color` command. Increase if your agent takes longer to initialize.

                                              *aiagent-config-show_header*
show_header ~
  Type: boolean  Default: `true`
  Show a non-interactive header above the terminal listing available
  keybindings.

                                          *aiagent-config-scroll_start_line*
scroll_start_line ~
  Type: number  Default: `9`
  Buffer line to jump to when entering scroll mode for the first time
  in a session. Skips the agent's startup preamble.

                                          *aiagent-config-idle_timeout_ms*
idle_timeout_ms ~
  Type: number  Default: `8000`
  Milliseconds of silence after activity before a background agent is
  flagged as needing attention. Set to `0` to disable idle alerts
  entirely. See |aiagent-idle|.

                                              *aiagent-config-idle_notify*
idle_notify ~
  Type: boolean  Default: `false`
  When `true`, also fire |vim.notify| when a background agent is flagged.
  The tab indicator is always shown regardless of this setting.
  See |aiagent-idle|.

                                                 *aiagent-config-colors*
colors ~
  Type: string[]
  Default: `{ "red", "blue", "orange", "green", "yellow", "pink", "cyan", "purple" }`
  Names must be ones Claude Code accepts: the plugin sends `/color <name>`
  to the agent at startup and an unknown name is rejected.
  Color cycle used when opening new agents. Each new agent gets the next
  color. Colors are sent to the agent via its `/color` command.

                                           *aiagent-config-mcp_max_width*
mcp_max_width ~
  Type: number  Default: `35`
  Maximum display-column width for the MCP status component in lualine
  before the carousel scroll activates. Increase this if your server
  names are long and you want more of them visible at once.
  See |aiagent-lualine-mcp|.

                                              *aiagent-config-mcp_scroll*
mcp_scroll ~
  Type: boolean  Default: `true`
  When `true`, the MCP status component scrolls through server names in
  a carousel when the total width exceeds |aiagent-config-mcp_max_width|.
  Set to `false` to always show the full list without scrolling.
  See |aiagent-lualine-mcp|.

                                              *aiagent-config-focus_cmd*
focus_cmd ~
  Type: function(entry) -> string[]|nil  Default: `nil`
  Command used to raise another Neovim instance's terminal window when
  you press <CR> in the machine-wide agent list (|:AgentList!|). Overrides
  the built-in tmux / iTerm2 / kitty / WezTerm detection; return `nil` to
  fall back to it. {entry} is a registry entry (see |aiagent-registry|),
  whose `term` field holds whatever pane identifiers were captured. >lua
    focus_cmd = function(entry)
      if entry.term.tmux then
        return { "tmux", "select-pane", "-t", entry.term.tmux }
      end
    end
<
  See |aiagent-registry-focus|.

                                            *aiagent-config-known_agents*
known_agents ~
  Type: table<string, string>  (symbolic name → CLI executable)
  Map of symbolic agent names to CLI executables. Extend this to add
  custom agents: >lua
    known_agents = { my_agent = "my-cli-binary" }
<

5. COMMANDS                                               *aiagent-commands*

                                                              *:AgentOpen*
:AgentOpen [Name [WTName [directory]]]
  Open an agent terminal. All arguments are optional.

  Name        Agent name (default: "AIAgent"). If an agent with this
              name is already running, switches to it instead.
  WTName      Worktree name. "-" is shorthand for using Name as the
              worktree name. See |aiagent-worktrees|.
  directory   Explicit directory for a new worktree. Error if the
              worktree already exists.

                                                             *:AgentClose*
:AgentClose [Name]
  Close the named agent (default: current agent). If it was the last
  agent, the terminal window is also closed.

                                                            *:AgentToggle*
:AgentToggle [Name]
  Toggle the agent window. Opens if closed, hides it (see |:AgentHide|)
  if the named agent is currently visible.

                                                              *:AgentHide*
:AgentHide
  Hide the agent terminal window without stopping the agent. The window
  and its header are closed but the agent's job and buffer stay alive, so
  the session keeps running in the background and can be brought back with
  |:AgentOpen|, |:AgentToggle| or |:AgentSwitch|. Contrast with
  |:AgentClose|, which stops the agent. Focus returns to the previous
  window.

                                                            *:AgentSwitch*
:AgentSwitch {Name}
  Switch the terminal window to display the named agent.

                                                               *:AgentSet*
:AgentSet {type}
  Set the agent type used for subsequent |:AgentOpen| calls.
  {type} must be a key in |aiagent-config-known_agents|.

                                                          *:AgentSetColor*
:AgentSetColor {color}
  Change the color of the current agent. Sends `/color {color}` to the
  CLI and refreshes the winbar tab.

                                                              *:AgentList*
:AgentList
  Print a list of running agents with their types. The current agent
  is marked with `*`. Only agents of THIS Neovim instance.

                                                             *:AgentList!*
:AgentList!
  Open the machine-wide agent list: every agent in every running Neovim
  instance, with its status, branch, directory and task. Press <CR> to
  bring the agent under the cursor to the front — its own Neovim switches
  to it and its terminal window is raised. `r` refreshes, `q` closes.
  See |aiagent-registry|.

                                                              *:AgentTask*
:AgentTask [text]
  Set the one-line task label shown for the current agent in
  |:AgentList!|. With no arguments the label is cleared and the list
  falls back to the agent's most recent prompt. >
    :AgentTask rewrite the diff viewer to use extmarks
<

                                                          *:AgentCloseAll*
:AgentCloseAll
  Close all running agents and the terminal window.

                                                       *:AgentSendContext*
:AgentSendContext
  Send all open buffer file paths to the current agent as @file
  references. Already-sent files are skipped.

                                                      *:AgentResetContext*
:AgentResetContext
  Clear the list of files that have been sent as context. The next
  |:AgentSendContext| will re-send all open buffers.

                                                     *:AgentSendSelection*
:{range}AgentSendSelection
  Send the visual selection to the current agent as a markdown code
  block. Opens the agent if not already running.

                                                  *:AgentSendDiagnostics*
:{range}AgentSendDiagnostics
  Collect LSP diagnostics for the current buffer and send them to the
  agent as a formatted prompt. The agent is focused and left in insert
  mode with the text ready — press Enter to start the analysis.

  Without a range, all diagnostics in the current file are included.
  With a range (e.g. `:'<,'>AgentSendDiagnostics`), only diagnostics
  whose line falls within the selected lines are included.

  The prompt includes:
    - A brief description asking the agent to analyse and suggest fixes
    - The full file path
    - Active language server name(s) and their compiler/workspace settings
    - All matching diagnostics sorted by line and column, wrapped in a
      fenced ```` ```<Errors> ```` block with severity, line, column,
      message, and source

  Diagnostics are sorted by line then column. Severity labels used:
    ERROR   vim.diagnostic.severity.ERROR
    WARN    vim.diagnostic.severity.WARN
    INFO    vim.diagnostic.severity.INFO
    HINT    vim.diagnostic.severity.HINT

  Opens the agent if not already running.
  See also |aiagent.send_diagnostics()|.

                                                              *:AgentDiff*
:AgentDiff [session]
  Open the prompt-history diff viewer. With no argument, opens the
  current agent's session; pass a session id to view an older one.
  Opens in a new tabpage. See |aiagent-prompt-history|.

                                                              *:AgentChat*
:AgentChat
  Close the prompt-history viewer and return to the agent chat.

                                                          *:AgentSessions*
:AgentSessions[!]
  Pick a captured prompt-history session from a list (newest first).

  Without `!`, selects the session to *continue capturing into*: new
  prompts are appended to the chosen session instead of the Claude-assigned
  one (writes `.prompt-history/active-session`).

  With `!`, instead loads the chosen session's prompt history into the
  running agent: it builds a primer — each prompt annotated with the files
  it changed and the diff it produced — and types it into the agent's input
  *without submitting*, so you can review it and press Enter. This
  re-orients the agent on a previous session's intent. It is not a
  conversation replay (the assistant's side is not captured) and is
  deliberately not the same as Claude's `--resume`.
  See |aiagent.prompt_history_load_context()|.

:AgentFind              Find any past Claude session on this machine and load
:AgentFind!             it back into an agent. `!` also lists the promptless
                        stubs Claude Code leaves behind. Documented in full
                        under |aiagent-find-session|.

                                                       *:AgentInstallSkill*
:AgentInstallSkill[!] [name]
  Install a bundled Claude skill into `~/.claude/skills/<name>/`. With no
  argument, installs every bundled skill (`prompt-history`, `pr-review`).
  Substitutes this install's hook paths, and for `prompt-history` prompts
  to wire the capture hooks into `~/.claude/settings.json` (required for
  capture). Refuses to overwrite an existing skill install unless called
  with `!`. See |aiagent-prompt-history|, |aiagent-pr-review|,
  |aiagent.install_skill()|, |aiagent.install_hooks()|.

                                                                *:AgentPR*
:AgentPR [number]
  Open the pull request review viewer. With no argument, pick from the
  repository's open PRs. Checks the PR head out into a worktree and opens
  a before|after diff over the merge base. See |aiagent-pr-review|.

                                                           *:AgentPRClose*
:AgentPRClose
  Close the review viewer and return to chat. The draft review is kept.

                                                          *:AgentPRReview*
:AgentPRReview [number] [agent]
  Brief the agent on the PR under review — title, changed files, the diff,
  and how to propose comments — by typing a primer into its input *without
  submitting*, so you review it and press Enter. Anything the agent then
  proposes lands in your draft marked `?`; nothing it writes is posted.
  See |aiagent-pr-review-agent|.

                                                          *:AgentPRSubmit*
:AgentPRSubmit
  Submit the draft review: checks whether the PR has moved, asks for a
  verdict, and posts every comment in one call. See |aiagent-pr-submit|.

                                                         *:AgentPRDiscard*
:AgentPRDiscard
  Throw the draft review away, after confirming. Unrecoverable.

6. KEYMAPS                                                 *aiagent-keymaps*

These keymaps are active inside the agent terminal buffer.

Terminal mode ~
  <C-\><C-n>    Exit terminal mode and return to the previous window
  <C-\><C-s>    Enter scroll mode (stay in agent window)
  <C-\><C-a>    Cycle to the next agent
  <C-\><C-c>    Send open buffer context (see |:AgentSendContext|)
  <C-\><C-v>    Paste the unnamed register `"` into the terminal input
  <C-\><C-d>    Open the prompt-history diff viewer (see |:AgentDiff|)
  <C-\><C-r>    Search input history (agent-specific)
  <C-\><C-l>    List agents in all Neovim instances (see |:AgentList|)
  <C-\><C-t>    Open the session history tree (see |:AgentTree|)
  <C-\><C-f>    Find a past session and load it back (see |:AgentFind|)

Scroll mode (normal mode inside terminal buffer) ~
  i             Exit scroll mode and resume terminal input
  <C-\><C-n>    Exit scroll mode and return to the previous window
  Any normal-mode motion (j, k, /, ?, G, etc.) to browse history

Scroll mode position memory ~
  - First entry: jumps to |aiagent-config-scroll_start_line|
  - Re-entry: restores the last cursor position from the previous
    scroll session

7. LUA API                                                    *aiagent-api*

All public functions are on the `require('aiagent')` table.

                                                    *aiagent.setup()*
setup({opts})
  Initialize the plugin and register autocmds. Safe to call multiple
  times (autocmds are cleared and re-registered via the AIAgent augroup).
  See |aiagent-config| for available options.

                                                     *aiagent.open()*
open({name}, {wtname}, {directory})
  Programmatic equivalent of |:AgentOpen|.

                                                    *aiagent.close()*
close({name})
  Programmatic equivalent of |:AgentClose|.

                                                   *aiagent.toggle()*
toggle({name})
  Programmatic equivalent of |:AgentToggle|.

                                                     *aiagent.hide()*
hide()
  Programmatic equivalent of |:AgentHide|. Closes the agent window and
  header while leaving the agent job and buffer running.

                                                   *aiagent.resize()*
resize()
  Re-apply the agent column's remembered share of the screen to the
  current screen size. Called automatically on |VimResized| when
  |aiagent-config-auto_resize| is on; call it by hand after changing
  'columns' yourself. Does nothing when the agent window is closed.

                                                   *aiagent.switch()*
switch({name})
  Programmatic equivalent of |:AgentSwitch|.

                                                      *aiagent.set()*
set({type})
  Programmatic equivalent of |:AgentSet|.

                                                *aiagent.set_color()*
set_color({color})
  Programmatic equivalent of |:AgentSetColor|.

                                             *aiagent.send_context()*
send_context({agent_name})
  Send unsent open buffers as context. Returns the number of files sent.

                                            *aiagent.reset_context()*
reset_context({agent_name})
  Clear sent-files tracking so all buffers will be re-sent next time.

                                         *aiagent.pending_context_count()*
pending_context_count({agent_name})
  Return the number of open buffers not yet sent as context.

                                          *aiagent.send_selection()*
send_selection({agent_name})
  Send the last visual selection as a markdown code block.

                                        *aiagent.send_diagnostics()*
send_diagnostics({agent_name}, {line1}, {line2})
  Collect LSP diagnostics for the current buffer and send a formatted
  prompt to the agent. Programmatic equivalent of |:AgentSendDiagnostics|.

  {agent_name}  string|nil  Agent to target (default: current agent)
  {line1}       number|nil  First line of range, 1-indexed (nil = whole file)
  {line2}       number|nil  Last line of range, 1-indexed (nil = whole file)

  Before sending, `\x1bi` is written to the terminal pty so that agents
  using vim keybindings (e.g. Claude's vim mode) are guaranteed to be in
  insert mode.

                                                 *aiagent.is_open()*
is_open()
  Return `true` if the terminal window is currently visible.

                                                    *aiagent.list()*
list()
  Return a list of running agent names (sorted alphabetically).

                                              *aiagent.print_list()*
print_list()
  Notify the running agents via |vim.notify|. Equivalent of |:AgentList|.

                                                  *aiagent.list_all()*
list_all()
  Return every live agent published on this machine as a list of registry
  entries, across all Neovim instances. See |aiagent-registry| for the
  entry fields.

                                                  *aiagent.show_all()*
show_all()
  Open the machine-wide agent list. Equivalent of |:AgentList!|.

                                                  *aiagent.set_task()*
set_task({text}, {name})
  Set the task label for an agent ({name} defaults to the current agent).
  An empty {text} clears it. Equivalent of |:AgentTask|.

                                              *aiagent.close_all()*
close_all()
  Close all agents and windows. Equivalent of |:AgentCloseAll|.

                                   *aiagent.bufferline_name_formatter()*
bufferline_name_formatter({buf})
  Name formatter for bufferline.nvim. See |aiagent-bufferline|.

                                                *aiagent.lualine_label()*
lualine_label()
  Returns a display string for lualine section A when the current buffer
  is the active agent terminal. Returns `nil` otherwise (caller should
  fall back to the normal mode string).

  Values returned:
    `"Agent: Claude"`       agent terminal in input mode
    `"Scroll Mode: Claude"` agent terminal in scroll mode
    nil                     any other buffer

                                                *aiagent.lualine_color()*
lualine_color()
  Returns a lualine color table for the section A component, or `nil`
  when not in the agent terminal (allowing the theme default).

  Values returned:
    `{ bg = '#0891b2', fg = '#ffffff' }`  input mode  (cyan)
    `{ bg = '#7c3aed', fg = '#ffffff' }`  scroll mode (purple)
    nil                                   other buffers

                                               *aiagent.lualine_branch()*
lualine_branch()
  Returns the current git branch of the active agent's worktree when
  the agent terminal is focused (determined via `git branch --show-current`
  in the worktree directory). Returns `nil` otherwise.

  Typical lualine usage (falls back to gitsigns for normal buffers): >lua
    function()
      return require('aiagent').lualine_branch()
          or vim.b.gitsigns_head or ''
    end
<
                                                  *aiagent.lualine_mcp()*
lualine_mcp()
  Returns a string listing all connected MCP servers, suitable for a
  lualine component. See |aiagent-lualine-mcp|.

                                            *aiagent.lualine_mcp_color()*
lualine_mcp_color()
  Returns `{ fg = '#22c55e' }` (green) once the MCP server list has
  loaded, or `{ fg = '#94a3b8' }` (grey) while the initial query is
  still running.

                                                 *aiagent.mcp_refresh()*
mcp_refresh()
  Clears the MCP server cache and immediately triggers a fresh
  `claude mcp list` query. Use this after changing your Claude MCP
  configuration so the statusline updates without waiting for the
  30-second cache to expire.

                                              *aiagent.current_session()*
current_session()
  Resolve the running agent's Claude Code session via its PID and
  `~/.claude/sessions/<pid>.json`. Returns `{ id, cwd }`, or `nil` when
  no agent is running or the session file can't be read.

                                         *aiagent.prompt_history_open()*
prompt_history_open({session})
  Open the prompt-history viewer. {session} is an optional session id
  (default: the current agent's session). Any open viewer is closed
  first so newly captured prompts are picked up. Programmatic
  equivalent of |:AgentDiff|. See |aiagent-prompt-history|.

                                        *aiagent.prompt_history_close()*
prompt_history_close()
  Close the prompt-history viewer. Equivalent of |:AgentChat|.

                                         *aiagent.prompt_history_list()*
prompt_history_list({load_context})
  Present a |vim.ui.select| picker of captured prompt-history sessions
  (newest first, each labelled with its turn count, start time and first
  prompt; the active capture session is marked with `*`). Programmatic
  equivalent of |:AgentSessions|.

  {load_context}  boolean|nil
    falsy  Pick the session to *continue capturing into*. Writes the chosen
           id to `.prompt-history/active-session` so the capture hook appends
           new prompts there instead of Claude's own session id. A
           `(default)` pseudo-entry restores the normal behaviour. If the
           diff viewer is open it follows the selection.
    true   Pick a session whose history is loaded into the running agent via
           |aiagent.prompt_history_load_context()| (the `:AgentSessions!`
           bang). The `(default)` entry is omitted in this mode.

                                  *aiagent.prompt_history_load_context()*
prompt_history_load_context({session}, {agent_name})
  Build a primer from a captured session — each prompt annotated with the
  files it changed and the diff it produced (built with
  `git diff --no-ext-diff`) — and TYPE it into the agent's input *without
  submitting*, so you review it
  and press Enter. This re-orients the agent on a previous session's intent;
  it is NOT a conversation replay (the assistant's side is not captured) and
  is deliberately not the same as Claude's `--resume`.

  {session}     string    prompt-history session id to load
  {agent_name}  string|nil  agent to target (default: current agent, or a
                            freshly opened `AIAgent`)

  As with |aiagent.send_diagnostics()|, `\x1bi` is written to the terminal
  first so agents using vim keybindings land in insert mode.

                                                     *aiagent.pr_open()*
pr_open({number})
  Open the PR review viewer. {number} is a PR number; with nil, a picker of
  the repository's open PRs is shown. Programmatic equivalent of |:AgentPR|.
  See |aiagent-pr-review|.

                                                    *aiagent.pr_close()*
pr_close()
  Close the review viewer, keeping the draft. Equivalent of |:AgentPRClose|.

                                                   *aiagent.pr_submit()*
pr_submit()
  Submit the open draft review. Equivalent of |:AgentPRSubmit|. See
  |aiagent-pr-submit|.

                                                  *aiagent.pr_discard()*
pr_discard()
  Discard the open draft review after confirming. Equivalent of
  |:AgentPRDiscard|.

                                                   *aiagent.pr_review()*
pr_review({number}, {agent_name})
  Build a primer for the PR under review — title, changed files, the unified
  diff (via `git diff --no-ext-diff`), and the call an agent uses to propose
  comments — and TYPE it into the agent's input *without submitting*, the
  same path as |aiagent.send_diagnostics()|. Equivalent of |:AgentPRReview|.

  {number}      string|number|nil  defaults to the open review
  {agent_name}  string|nil         defaults to the current agent

pr_comment({spec})

bundled_skills()

8. GIT WORKTREES                                          *aiagent-worktrees*

Each agent can be associated with a git worktree — an isolated checkout of
the repository on a dedicated branch. Worktrees are persistent across Neovim
sessions.

Naming convention ~
  Branch:    `agent/{slug}`
  Directory: `$TMPDIR/nvim-agent-{repo}-{slug}`

  Where {slug} is the worktree name lowercased with non-alphanumeric
  characters replaced by `-`, and {repo} is the repository directory name
  (prevents collisions across different repos).

Opening with a worktree ~
>
  :AgentOpen MyFeature -          " uses "MyFeature" as WTName
  :AgentOpen MyFeature MyFeature  " same, explicit
  :AgentOpen MyFeature feat /path " creates worktree at /path
<

Auto-reconnect ~
  On `:AgentOpen Name` (no WTName), the plugin scans the git worktree
  list for a worktree whose branch matches `refs/heads/agent/{slug}`.
  If found, the agent reconnects to it silently.

File redirection ~
  While a worktree agent is active, opening files with `:e` inside the
  same repository automatically redirects to the worktree version.
  Bufferline tabs for redirected files are prefixed with the worktree
  slug (requires |aiagent-bufferline| configuration).

  To bypass redirection: >
    :noautocmd e path/to/file
<
Removing a worktree ~
>
  git worktree remove /path/to/worktree
  git branch -d agent/my-feature
<

9. IDLE ATTENTION ALERTS                                      *aiagent-idle*

When you start a long-running job in one agent and switch to another, the
plugin watches for the first agent to finish or pause for input. When a
background agent has produced new output and then gone silent for
|aiagent-config-idle_timeout_ms| milliseconds, its winbar tab is highlighted
and a `●` symbol is appended to the name: >

  [ Review ] [ Feature ● ]
<
The alert clears automatically when you switch back to that agent. If the
agent resumes work (produces more output), the alert is also cleared
immediately.

Detection ~
  The plugin records the terminal buffer's line count each time you visit
  an agent. While the agent is in the background:

  - New lines added to the buffer update an internal timestamp
  - Cursor blinks, prompt redraws, and in-place updates (which do not
    add lines) are ignored — they cannot re-trigger an alert after a visit
  - Once the new-line timestamp is older than |aiagent-config-idle_timeout_ms|,
    the tab is flagged

  Agents that are idle because they have not been asked anything are never
  flagged — only agents that were actively producing output and then stopped.

Configuration ~
  See |aiagent-config-idle_timeout_ms| and |aiagent-config-idle_notify|.

  To disable idle alerts: >lua
    require('aiagent').setup({ idle_timeout_ms = 0 })
<
  To also receive a |vim.notify| message when an agent is flagged: >lua
    require('aiagent').setup({ idle_notify = true })
<

10. LSP DIAGNOSTICS                                     *aiagent-diagnostics*

|:AgentSendDiagnostics| collects LSP diagnostics for the current buffer via
`vim.diagnostic.get()` and sends a structured prompt to the agent.

Whole-file usage ~
>
  :AgentSendDiagnostics
<
  All diagnostics for the current buffer are included.

Range usage ~
>
  :'<,'>AgentSendDiagnostics
<
  Only diagnostics whose line falls within the visual selection are sent.
  Useful for focusing on a specific function or block.

Prompt structure ~

  The message typed into the agent prompt contains:

    1. A brief instruction asking the agent to analyse and suggest fixes
    2. `**File:** /absolute/path/to/file`
    3. `**Language Server(s) and compiler options:**` listing each active
       LSP client and its `config.settings` (or `init_options`) as JSON
    4. `**Errors:**` followed by a fenced block:
>
       ```<Errors>
       [ERROR] line 10, col 5: Undefined variable 'x' (lua_ls)
       [WARN]  line 14, col 1: Unused import (lua_ls)
       ```
<
    5. A closing instruction to explain what is wrong and how to fix it

  The text is NOT submitted automatically — the agent is focused in insert
  mode with the prompt ready, and the user presses Enter to send.

Vim mode compatibility ~

  Before the text is sent, `<Esc>i` is written to the terminal pty. This
  ensures agents with vim keybindings (such as Claude's vim mode) are in
  insert mode regardless of their previous state.

Suggested mapping ~
>lua
  vim.keymap.set("n", "<leader>ad", "<cmd>AgentSendDiagnostics<cr>",
    { desc = "Send LSP diagnostics to agent" })
  vim.keymap.set("v", "<leader>ad", "<cmd>AgentSendDiagnostics<cr>",
    { desc = "Send LSP diagnostics (selection) to agent" })
<

12. LUALINE INTEGRATION                                    *aiagent-lualine*

AIAgent provides optional helpers for lualine.nvim that surface agent state
in your statusline. None of these require any setup beyond adding them to
your lualine configuration.

Section A — Agent mode ~                              *aiagent-lualine-mode*

  Replaces the standard mode indicator with the agent name and current
  mode when the agent terminal window is focused: >lua

    lualine_a = {
      {
        function()
          return require('aiagent').lualine_label()
              or require('lualine.utils.mode').get_mode()
        end,
        color = function()
          return require('aiagent').lualine_color()
        end,
      },
    },
<
  The component color changes automatically:
    Cyan   (#0891b2)  when in normal agent input mode
    Purple (#7c3aed)  when in scroll mode
    Theme default     for all other buffers

Section B — Worktree branch ~                        *aiagent-lualine-branch*

  Shows the real git branch of the active agent's worktree when the agent
  terminal is focused. Falls back to gitsigns for all other buffers: >lua

    lualine_b = {
      {
        function()
          return require('aiagent').lualine_branch()
              or vim.b.gitsigns_head or ''
        end,
        icon = '\u{E0A0}',
      },
      'diff', 'diagnostics',
    },
<
  The branch is read with `git -C {worktree} branch --show-current` so it
  reflects the actual checked-out branch, not an assumed name.

Section X — MCP server status ~                         *aiagent-lualine-mcp*

  Displays connected MCP servers queried from `claude mcp list`. Results
  are cached for 30 seconds. Only servers reported as `✓ Connected` are
  shown; auto-discovered `claude.ai` servers are filtered out. >lua

    lualine_x = {
      {
        function() return require('aiagent').lualine_mcp() end,
        color = function() return require('aiagent').lualine_mcp_color() end,
      },
      'encoding', 'filetype',
    },
<
  Example output: >
    MCP: ✓ atlassian  ✓ github
<

Carousel scroll ~                               *aiagent-lualine-mcp-scroll*

  When the MCP server list is wider than |aiagent-config-mcp_max_width|
  columns, the component switches to a fixed-width scrolling carousel:

  - A window of `mcp_max_width` columns slides through the server list
  - The window advances one character every 300 ms via a `vim.uv` timer
  - The loop is seamless: a separator gap (`   `) is appended before the
    text repeats, so the scroll wraps smoothly
  - The component is padded to a fixed width so the statusline does not
    resize as the text scrolls
  - The timer is stopped automatically when the content fits within
    `mcp_max_width` (e.g. after servers disconnect) or when there are no
    servers to display

  To disable scrolling: >lua
    require('aiagent').setup({ mcp_scroll = false })
<
  To widen the display area: >lua
    require('aiagent').setup({ mcp_max_width = 50 })
<
  To force an immediate refresh after changing Claude config: >lua
    require('aiagent').mcp_refresh()
<

13. PROMPT HISTORY                                  *aiagent-prompt-history*

Browse, prompt by prompt, the code an agent session changed. Each prompt is
captured as a pair of git tree snapshots (before the turn and after the agent
finishes); the viewer reconstructs a native side-by-side diff of the files that
changed.

CAPTURE ~

Two Claude Code hooks (shipped in the plugin's `hooks/` directory) record the
snapshots. Wire them into your user `~/.claude/settings.json`: >
    UserPromptSubmit -> prompt_snapshot.sh pre   (tree at submit time)
    Stop             -> prompt_snapshot.sh post  (tree after the turn)
<
Each turn is appended to `<repo>/.prompt-history/sessions/<id>.jsonl` with the
prompt text, before/after tree SHAs, and changed files. The path is anchored on
the git common dir, so all worktrees of a repo share one history. Trees are
built in a temporary index (committed + uncommitted + untracked files, with
`.prompt-history/` excluded), so they survive commits and capture
work-in-progress. The hooks write no stdout and always exit 0, so a capture
failure never blocks a turn. Requires `git` and `jq` on PATH; add
`.prompt-history/` to your `.gitignore`.

VIEWER ~

Run |:AgentDiff| to open the viewer in a new tabpage (the agent terminal is
left untouched). The left column holds the prompt list and the changed-file
list; the right column shows the selected file's `before | after` diff via
native |:diffthis| at the top and the full prompt text at the bottom. Keys
inside the viewer:
>
    j / k       Move through the prompt list (or file list when focused)
    ]f / [f     Cycle to the next / previous changed file
    q           Close the viewer and return to the agent chat
<
The current turn is only recorded once it finishes, so a session with no
completed turns yet opens empty.

INSPECT FROM THE TERMINAL ~

`hooks/prompt_history_inspect.sh` lists and dumps history without the viewer: >
    prompt_history_inspect.sh                    list sessions for this repo
    prompt_history_inspect.sh <session-id>       dump a session's prompts
    prompt_history_inspect.sh <session-id> <n>   changed files for prompt #n
<
SESSIONS ~

|:AgentDiff| defaults to the running agent's live session, but a repo
accumulates one JSONL file per session under `.prompt-history/sessions/`.
|:AgentSessions| picks among them (newest first; the active capture session is
marked `*`) and has two modes:

  :AgentSessions      Choose the session to *continue capturing into*. The
                      chosen id is written to `.prompt-history/active-session`
                      and the capture hook appends subsequent prompts there
                      rather than to Claude's own session id. Useful for
                      keeping one continuous history across `--resume` restarts
                      or several short Claude sessions. Pick `(default)` to
                      revert to Claude's session id. If the diff viewer is open
                      it follows the selection.

  :AgentSessions!     Load the chosen session's prompt history back into the
                      running agent. A primer — every prompt annotated with the
                      files it changed and the diff it produced — is typed into
                      the agent's input *without submitting*, so you review it
                      and press Enter. This re-orients the agent on an earlier
                      session's intent. It is not a conversation replay (the
                      assistant's replies are not captured) and is deliberately
                      distinct from Claude's `--resume`.

See |aiagent.prompt_history_list()| and
|aiagent.prompt_history_load_context()|.

CLAUDE SKILL ~

The plugin bundles a `prompt-history` Claude skill that lets an agent drive the
viewer for you. Install it with |:AgentInstallSkill|; it is copied into
`~/.claude/skills/prompt-history/` with this install's hook paths substituted
in, and you are then prompted to wire the capture hooks above into
`~/.claude/settings.json` automatically (idempotent; a `.bak` is written).

See also |:AgentDiff|, |:AgentChat|, |:AgentSessions|, |:AgentInstallSkill|,
|aiagent.prompt_history_open()|, |aiagent.prompt_history_list()|,
|aiagent.install_skill()|.

14. AGENT REGISTRY                                       *aiagent-registry*

When Neovim is open in several terminal windows — each in its own directory,
each with its own agents — |:AgentList| only sees the instance you are in.
|:AgentList!| sees them all: >

   ▶ AIAgent   busy      agent/history   …/lazy/AIAgent  add a global list
     Refactor  idle 16m  agent/refactor  ~/Repo/app      why does load retry
<
Columns are: current-agent marker, agent name (in the agent's colour), status,
branch, directory, and task. `▶` marks the agent currently shown in THIS
instance. Press <CR> on a row to bring that agent to the front, `r` to
refresh, `q` to close.

STATUS ~                                          *aiagent-registry-status*

`busy` / `idle` come from Claude Code's own per-process session file
(`~/.claude/sessions/<pid>.json`), not from the plugin. `idle` means the agent
has stopped and is waiting on you — which is why it is the highlighted state —
and is followed by how long it has been waiting. Agents that publish no such
file (non-Claude CLIs) show `-`.

TASK LABEL ~                                        *aiagent-registry-task*

The task column answers "what is this one working on". By default it is the
agent's most recent prompt, read from the session transcript. Set an explicit
label with |:AgentTask| when the last prompt is not a useful summary (it often
is not — "yes", "continue", "run the tests"); the explicit label always wins,
and clearing it returns to the derived one.

HOW IT WORKS ~                                    *aiagent-registry-sidecar*

Each instance publishes one small JSON sidecar per agent into
`$XDG_STATE_HOME/aiagent/agents/` (default `~/.local/state/aiagent/agents/`),
named `<nvim-pid>-<agent>.json`. Sidecars are written when an agent is opened,
switched to, or given a task label, and removed when it is closed.

No instance ever talks to another to build the list, and there is no
heartbeat. Instead, liveness is verified on read: an entry whose owning Neovim
process or whose agent process is gone is dropped and its sidecar unlinked. A
crashed instance therefore leaves nothing behind, and the first list after the
crash cleans up after it.

Entries carry the agent name, type, colour, worktree slug, task label, the
Neovim server socket (|v:servername|), the agent's pid, and a `term` table
identifying the terminal pane the instance is displayed in. Status, session id,
cwd and the derived task label are merged in from Claude Code's own files at
read time, so they are never stale.

FOCUS ~                                            *aiagent-registry-focus*

<CR> does two things: it asks the owning instance to switch to that agent
(over its |--remote-expr| server socket), then raises the terminal pane that
instance is displayed in. Pane raising is best-effort and picked from what was
captured at publish time, in this order:

  tmux       `$TMUX_PANE`         → `tmux switch-client`
  iTerm2     `$ITERM_SESSION_ID`  → `osascript` session select
  kitty      `$KITTY_WINDOW_ID`   → `kitten @ focus-window`
  WezTerm    `$WEZTERM_PANE`      → `wezterm cli activate-pane`

A multiplexer takes precedence over the emulator, since raising the pane is
what actually reveals the agent. If none is detected you still get a notify
telling you which directory and Neovim pid the agent belongs to; set
|aiagent-config-focus_cmd| to teach it your terminal.

15. HISTORY TREE                                     *aiagent-history-tree*

                                                                  *:AgentTree*
:AgentTree [session]    Show the session's history as a tree in a popup and
                        jump to any point in it. Defaults to the current
                        agent's session.

A Claude Code session is a TREE, not a straight line. `/rewind` does not throw
the abandoned turns away — it starts a sibling branch, and every branch stays
in the same transcript file. |:AgentTree| draws that tree and lets you move
between its branches: >

   ● We just added the command "AgentList!" …  Tue 10:34    1.1M  17 tools
   ├─╮
   │ ○ actually split it into two commits      Tue 10:40    380k  8 files
   │    ╰ tip · 2 turns
   │
   ● reload the module and reopen the agent    Tue 10:36    520k  6 tools
   ● Run the rewind experiment and show me…    Wed 14:31    4.8M  36 tools
   ▶ That looks good. I want the window to…      15:16    5.5M  history.lua
<
Nodes are the prompts YOU typed; each row summarises the assistant and tool
traffic that answered it. `●` is a turn on the path you are currently on, `○`
one on a branch you have left, and `▶` is where you are now. Depth never
indents — only forks do — so a long linear session stays in one column, the
way `git log --graph` keeps its trunk in a fixed gutter.

The columns after the prompt are the time the prompt was sent, the tokens SENT
answering it, and what the turn did (up to two files it touched, else a tool
count, else `—`).

The token figure is what went TO the model, not what came back: for every API
call the turn made, `input + cache_creation + cache_read`, summed. Turns run to
millions because each step of an agentic turn re-sends the whole conversation,
so it reads as a per-turn cost rather than as context size — a one-line "push
it" costs 258k, while a turn that ran 36 tools costs 4.8M. Cached tokens are
included: they were still sent, and they are still what makes a long session
expensive.

Every turn gets its own row — nothing is rolled up. The popup opens as tall as
the history needs, capped at 60 rows, or at 80% of the screen when the screen
cannot spare 60. The cursor starts on your current position at the bottom of
the viewport, so a longer history scrolls back into the past above it.

Press <CR> to jump to the turn under the cursor, `f` to fork a new agent from
it (see |:AgentFork|), `q` to close.

HOW JUMPING WORKS ~                                  *aiagent-history-jump*

Claude Code records its position in the transcript as an entry of the form: >

   {"type":"last-prompt","lastPrompt":"…","leafUuid":"<uuid>","sessionId":"…"}
<
The LAST such entry wins. Jumping therefore means: stop the agent, append a
pointer naming the target entry, and restart with `--resume`. Context is then
assembled by walking from that entry to the root.

The same mechanism serves both directions. Repointing at an ancestor IS a
rewind, so no distinction is made between a turn on the current path and one
on a branch that was rewound away — which also avoids depending on `/rewind`,
an interactive dialog with no programmatic entry point.

A pointer is only honoured when it names a LEAF of the transcript: at a node
that still has children it is silently ignored and the newest leaf is resumed
instead. Since that describes every rewind, a synthetic anchor entry is
appended below the target first and the pointer names that, which is what makes
the target a real fork point.

Two consequences worth knowing:

  - The agent process necessarily RESTARTS. The job must be stopped before the
    pointer is written, because a live session writes its own `last-prompt` at
    the end of every turn and would clobber it.
  - Nothing is destroyed. Every branch keeps its own tip, so a jump is always
    reversible by jumping back.

Selecting the turn you are already on is a no-op. The jump is only implemented
for Claude agents; other agent types report that and do nothing.

FORKING FROM A NODE ~                                *aiagent-history-fork*

                                                                  *:AgentFork*
:AgentFork [name [worktree]]
                        Fork a new agent from where the current agent stands.
                        Press `f` on a row in |:AgentTree| to fork from an
                        earlier point instead. With no arguments a small menu
                        offers the choices below; an empty `worktree` argument
                        means "share the source agent's", which skips it.

The menu is the plugin's own float, not |vim.ui.select|: number keys pick an
option directly, <CR> takes the row under the cursor, and `q` or <Esc> cancels
(saying so, rather than doing nothing). A filtering picker is the wrong shape
for a three-way choice, and a cmdline prompt is easy to miss entirely beside a
busy agent terminal.

A jump moves the agent you have; a fork leaves it alone and starts a second
one from the chosen point. `--fork-session` resumes under a NEW session id and
Claude Code copies the walked path into the new transcript (rewriting every
entry's `sessionId`), so the fork is genuinely independent — it is not a view
into the source session, and the two cannot clobber each other.

The fork gets its own colour, tab and registry entry, and a task label naming
the turn it came from, so |:AgentList| explains why it exists.

Choosing a worktree gives the fork isolated files (branch `agent/{slug}`, as
|:AgentOpen| creates), at the cost that the paths in its inherited context
refer to the SOURCE tree. Sharing the source's tree keeps every remembered
path valid but means two agents editing the same files.

The source agent is never stopped. Its recorded position does move while the
fork reads the transcript and is restored once the fork has started; that
restore is best-effort by design, because the source's own next turn appends
newer entries which supersede any stale pointer anyway.

These transcript entry types are undocumented internals of Claude Code. If a
future version changes them the tree reports that it cannot be read rather
than guessing.

16. FINDING PAST SESSIONS                            *aiagent-find-session*

                                                                  *:AgentFind*
:AgentFind              Find any past Claude session on this machine and load
                        it back into an agent.
:AgentFind!             The same, but also lists the promptless stubs Claude
                        Code leaves behind for every start that never got a
                        question. They outnumber the real sessions, which is
                        why they are hidden by default.

Also bound to <C-\><C-f> inside the agent terminal.

Closing a terminal does not lose the conversation in it. Claude Code keeps one
transcript per session under `~/.claude/projects/` and never deletes them, so
every session you have ever run is still on disk. |:AgentFind| lists them,
newest first: >

   ● 13:05   38  AgentList key bindings   We just added the command "Agent…  AIAgent
     13:01   31  AgentList key bindings   We just added the command "Agent…  AIAgent
     11:31    4  Poem about dwarves       Write a poem about dwarves.        Repo
<
The columns are: whether the session is live in a running agent (`●`), when it
was last touched, how many prompts you typed in it, Claude Code's own name for
it, its opening prompt, and the directory it ran in. Searching matches all of
those plus the session's LAST prompt and its id, so "what was I doing at the
end of that" finds it too.

The picker is |telescope| when telescope.nvim is installed — the preview pane
shows that session's |:AgentTree|, so you can see the shape of a conversation
before committing to it. Without telescope you get the plugin's own float,
where `/` searches, <CR> loads and `q` closes.

  <CR>          Load the session under the cursor
  <C-t>         Open that session's history tree instead (`t` in the float)

Sessions from EVERY project are listed, not just this one: a session resumes
by id regardless of which directory you resume it from, and scoping the list
to the current repo is the kind of filter that hides the thing you are looking
for. Type the directory name to narrow it.

HOW LOADING WORKS ~                                    *aiagent-session-load*

Loading resumes the session with `--resume <id> --fork-session`, so:

  - The archive is never written to. It stays exactly as it was and can be
    loaded again, as often as you like — including into two agents at once.
  - No `last-prompt` pointer is written either. With none, resume takes the
    session's newest leaf, which is precisely "carry on where I left off".

To start from an EARLIER point in a past session, open its tree instead
(<C-t> on the row) and fork from the turn you want; see |aiagent-history-fork|.

With an agent running, the load happens in place: same panes, same name, same
worktree, same colour — only the process and the history behind it change, the
way a jump does (see |aiagent-history-jump|). With no agent running, a fresh
one is opened in the current directory.

The loaded agent gets a task label naming the session, so |:AgentList| says
where it came from.

Two things to know:

  - The files in the recovered context are the paths the session saw. If it ran
    in a worktree that no longer exists, the conversation is intact but those
    paths are not.
  - Loading a session that is still live in another agent is safe — the fork
    only reads it — and is reported when it happens.

Scanning is a streamed read of each transcript, decoding only the lines that
can carry a prompt or a title, so a full corpus scan costs tens of
milliseconds rather than parsing megabytes of tool traffic.

17. PR REVIEW                                            *aiagent-pr-review*

`:AgentPR 123` brings a GitHub pull request into Neovim: the head is checked
out into a worktree, the diff opens in a before|after pair, and your comments
collect in a local draft until you submit them as one review.

The GitHub review UI collects comments into a PENDING review and posts them on
submit. That is one REST call, so this does the same thing with your own
editor, your own LSP, and your agent in the next split.

`gh` must be installed and authenticated (`gh auth login`);
`:checkhealth aiagent` reports both.

THE VIEWER ~                                        *aiagent-pr-review-keys*

The viewer opens in its own tabpage, so the agent terminal is untouched and
`q` returns you to chat with the draft intact.

  +----------+---------------------+---------------------+
  | help     |  BASE  (LEFT)       |  HEAD  (RIGHT)      |
  +----------+                     |                     |
  | files    |     :diffthis pair  |                     |
  +----------+                     |                     |
  | comments |                     |                     |
  +----------+---------------------+---------------------+
  | detail: the selected comment, else the PR + summary   |
  +-------------------------------------------------------+

  q         back to chat (the draft is kept)
  ca        comment on the cursor line, or on the visual selection
  cf        comment on the whole file
  cr        edit the review summary
  cs        submit the review
  ]f  [f    next / previous changed file
  ]r  [r    next / previous comment (selects its file, parks on its line)
  a         accept (or un-accept) the agent proposal under the cursor
  d         delete the comment under the cursor
  e  <CR>   edit the comment under the cursor

`a`, `d` and `e` are single letters that already mean something in a diff
pane, so they are mapped only in the panes where a comment is under the
cursor. Everything else works from any pane.

Note the keys deliberately avoid `gc`. Neovim 0.10+ maps `gc`/`gcc` as the
built-in comment operator, and on a read-only diff pane that fails with |E21|
rather than doing anything; pressing it here says which key to use instead.
`]c`/`[c` are left alone too — in a diff they are next/previous change, which
is worth more in a review than another binding of ours.

Remap any of them with `config.pr_keys` (|aiagent-config|); set one to `false`
to leave it unmapped: >
    require('aiagent').setup({
      pr_keys = { comment = '<leader>c', submit = false },
    })
<

Which pane the cursor is in decides which side of the diff a comment lands
on: the BASE pane is `LEFT` (the pre-change file), the HEAD pane is `RIGHT`.
Because both panes hold real file contents rather than a rendered patch, the
cursor's row IS the line number the GitHub API wants.

Comments you have already written show in the diff panes as a sign and the
first line of their text, so re-reading a file shows what you said about it.

WHICH LINES YOU CAN COMMENT ON ~                    *aiagent-pr-review-lines*

GitHub only accepts a comment on a line that is part of the PR's diff —
changed or context — and rejects the ENTIRE review when one comment is out of
bounds. There is no partial success. So the commentable lines are computed
from the diff up front and a comment outside them is refused at the cursor,
where it costs you nothing, rather than after the review is written.

THE DRAFT ~                                         *aiagent-pr-review-draft*

The draft lives in `$XDG_STATE_HOME/aiagent/reviews/` (default
`~/.local/state/aiagent/reviews/`), one JSON file per PR — outside the repo,
so it never shows in `git status`, and keyed on the PR rather than on the
Neovim instance, so it survives closing the viewer, closing Neovim, and
rebooting. Reopening `:AgentPR 123` picks it back up.

The review is pinned to the head SHA you started on. If the author pushes
while you are reading, reopening keeps you on the head your comments were
written against, and |:AgentPRSubmit| tells you which comments are affected
rather than silently retargeting them at code they were not about.

THE WORKTREE ~                                   *aiagent-pr-review-worktree*

The PR is checked out on branch `agent/pr-<n>` at
`$TMPDIR/nvim-agent-<repo>-pr-<n>`, following the same convention as agent
worktrees (|aiagent-worktrees|). Because the branch name matches, >
    :AgentOpen review pr-123
<
afterwards puts an agent in that same tree with the PR checked out. Like all
worktrees in this plugin it is persistent: closing the review does not remove
it.

LETTING THE AGENT PROPOSE COMMENTS ~                *aiagent-pr-review-agent*

`:AgentPRReview` types a primer into the agent — the PR, the changed files,
the diff, and how to call back in — without submitting it, so you read it
first and press Enter.

Comments the agent proposes arrive in your draft marked `?`. They are NOT
posted, and cannot be: |aiagent.pr_comment()| records everything an agent
writes with `origin = "agent"` and `accepted = false`, and the submit payload
excludes those. Press `a` on the ones worth keeping, `e` to reword one, `d`
to drop it. Only what you accept is posted, and only when you submit.

Install the bundled `pr-review` skill (|:AgentInstallSkill|) to teach the
agent the call and the line-validity rule.

SUBMITTING ~                                             *aiagent-pr-submit*

`gs` (or |:AgentPRSubmit|) walks four checks and then posts once:

  1. Any agent proposals you have not triaged are called out.
  2. The PR is re-read: if it has moved, you are told how many of your
     comments touch lines that have since changed, and choose.
  3. You pick the verdict — comment, request changes, approve, or leave the
     review PENDING on GitHub as a draft only you can see.
  4. Every comment goes in ONE call. On success the draft is deleted; on
     failure it is kept and GitHub's error is shown verbatim, because a 422
     names the path and line that caused it.

Requesting changes and commenting need a review summary; you are asked for
one if you have not written it.

NOT INCLUDED ~                                      *aiagent-pr-review-scope*

Reading and resolving existing review threads, replying to other people's
comments, suggested-change blocks, and CI status are all out of scope: they
need the GraphQL API rather than this one REST call, and share nothing with
the write path above.
